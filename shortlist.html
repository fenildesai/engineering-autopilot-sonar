Submission-ready summaries and delivery boundaries

1. Ripple — Submit

Submission headline: Recognition → consented expertise → introductions.

Problem: Existing workflows leave this outcome fragmented, difficult to find or reactive. The prototype targets one narrow, demonstrable user journey.

Proposed solution: Opt-in sample recognitions; agent extracts skills; flow asks permission; app shows ripple.

Technology: Power Apps = interface; Agent Builder = interpretation, matching or scenario facilitation; Power Automate = approved workflow, notification and recording; approved SharePoint list or Dataverse = demo data.

Two-day demo: Seed safe sample data → complete one user interaction → inspect agent output → approve action → see recorded result.

Scope & AI governance: Privacy and HR monitoring boundaries. Human review before consequential actions.

Technical feasibility: No assumed access to production Azure Bot, policy systems, repository execution, or privileged tenant APIs. Validate connector and licensing permissions in the hackathon tenant.

Innovation review: Showcase the outcome and feedback loop, not just chat.

Suggested two-day plan

Day 1: Build the Power App, create approved demo data, configure agent instructions and a single Power Automate flow.

Day 2: Connect the journey, test positive and failure cases, demonstrate approval/evidence, polish pitch and capture screenshots.

Before submitting: Check whether “Agent Builder” supports the required actions in your tenant, whether Power Apps can invoke the agent in your chosen setup, and which connectors/data stores are approved. If direct invocation is unavailable, trigger an agent-backed flow from Power Automate or use the agent interface separately; do not claim a working integration until verified.
